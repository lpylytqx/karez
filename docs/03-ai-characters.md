# AI 角色人设总览（人读版）

> 完整的、可直接送进 API 的 system prompt 在 [characters.json](D:\坎儿井\data\characters.json) 里。
> 本文是给你（创作者）看的速览：**先读这一页，再决定改哪个角色。**

---

## 一、为什么这样设计这七个角色

GDD 5.3 给了七个角色，但只写了身份和几个形容词。要真正驱动 AI，一个角色需要四样东西：

| 必需项 | 为什么 |
|---|---|
| **说话方式**（长短、口癖、禁忌） | 没有它，七个角色都会用同一种腔调说话——这是 AI 角色最大的通病 |
| **秘密** | 让对话有纵深。玩家逐渐发现的东西，比一开始就知道的全部更有意思 |
| **彼此关系** | 让角色之间能自发互动，这是 GDD「涌现性」的技术基础 |
| **行为规则** | 把性格翻译成可执行的条件判断，否则模型只会演一个"性格标签" |

**最重要的设计原则：每个角色都要有一个"不肯说的事"。** 这是他们不变成工具人的唯一保障。

## 二、七个角色的核心设计

| 角色 | 一句话内核 | 不肯说的 | 与玩家的关系弧线 |
|---|---|---|---|
| **老坎匠** | 手艺通神、嘴上刻薄、心里护人 | 兄弟死在那次塌方里；上游有暗河 | 从看不起 → 认了你 → 把你当徒弟/儿子 |
| **木卡姆艺人** | 表面快活的社交中枢，实际最懂人心 | 曾被赶出别的驿站；弟弟失散 | 从玩笑试探 → 记住了你的每个承诺 → 交心 |
| **哈萨克骑手** | 急于证明自己的年轻人 | 因丢羊被罚，丢过脸 | 从嘴硬 → 失败羞愧 → 真正的成长 |
| **商队掌柜** | 讲信用的生意人，三句不离价钱 | 商队已亏两年；带着一封密信 | 从买卖 → 长期合作 → 有限的交情 |
| **厨娘** | 管饭也管所有人的情绪 | 丈夫死于马匪劫掠；私下接济过穷人 | 一开始就接纳你 → 关键时刻说公道话 |
| **神秘旅人** | 从容不迫的观察者 | 全部（长线剧情的核心） | 从疏离 → 被你的善意松动 → 逐步交底 |
| **马匪头目** | 不是疯子，是算成本收益的生意人 | 当过驿卒；手下只够吃十天 | 从敌对 → 尊重 → 可能合作 |

## 三、几个刻意的设计决定

### 1. 老坎匠"讲原理的方式是骂你哪里做错了"
这是防止他变成"坎儿井知识播报器"的关键。民族文化如果由角色**讲授**，就变成了说教（违反 GDD 2.3 的原则：让文化活在日常里）。他讲的是**具体的人和事**——哪一年、谁死了、挖到多深出了什么事。

### 2. 叶尔兰（骑手）会失败
他的设定是"夸大能力"。如果玩家真派他去执行超出能力的任务，**他应该失败并因此羞愧**。这是他的角色弧光。一个永远成功的年轻角色没有成长可言。

### 3. 黑风（马匪）越平静越危险
明确禁止他咆哮、狂笑。他的威慑力来自克制。而且他的真实动机是**手下的粮只够十天**——他不是恶的化身，是被生存推着走的人。这让他可以谈判、可以转化。

### 4. 厨娘是唯一无条件善待神秘旅人的人
这个态度差异本身就是叙事线索。别人都在打量那个旅人，只有她给他饭吃、不问来历。旅人对她的感激是他唯一的裂缝。

### 5. 神秘旅人说的每句话都真实，但不完整
他不能故弄玄虚。玩家应该感觉到「这人知道的比说的多」，而不是「这人在装」。他会说"上游的井不是自然淤的"，但不说谁做的、为什么。

## 四、文化审核：请你优先处理这一页

每个角色的 `cultural_claims` 数组列出了其台词会涉及的文化事实断言。**这是你拿去找人核实的清单**，不必让人逐句读 prompt。

### 高风险项（建议先审这五条）

| 涉及角色 | 待确认内容 | 风险 |
|---|---|---|
| 厨娘 | 食物禁忌与待客礼节 | **宗教饮食规范极易出错，代价极大** |
| 神秘旅人 | 流亡者设定 + 坎儿井人为破坏情节 | 须避免影射任何现实群体或事件 |
| 马匪头目 | 多民族混杂出身与暴力犯罪的关联 | **民族形象风险** |
| 木卡姆艺人 | 木卡姆的表述准确性与演出场合 | 核心文化事实，不可简化失当 |
| 老坎匠 | 水权协商内容 | 涉及现实议题，表述须谨慎 |

### 审核人的交付格式

针对每一条给出三种结论之一：
1. **准确可用**
2. **需修改**（附修改建议）
3. **建议回避**（附理由）

系统已经预留了回避机制：`characters.json` 的 `safety_rules.blocked_topics` 会在 prompt 里明确禁止模型触碰这些话题，并要求角色用符合性格的方式带过，而不是解释为什么要回避。

> ⚠️ **审核通过前不要对外展示角色台词，也不要录演示视频。** 台词一旦录成视频就不好改了。

## 五、你要改的地方（这是你的创作，不是我的）

AI 只是执笔。以下这些应该由你亲自定，因为它们决定游戏的"魂"：

1. **神秘旅人到底是谁、坎儿井为什么淤塞** —— 这是贯穿全局的悬念，必须你定
2. **七个角色的秘密是否符合你想要的故事走向**
3. **有没有想加的角色**（GDD 提到可增删：艾德莱斯绸匠人、放牧老人、客栈老板、学徒少年）
4. **口头禅是否自然** —— 读出来听听，不像人话就改

改完直接编辑 [characters.json](D:\坎儿井\data\characters.json)，`system_prompt` 字段就是给模型的原文。改完跑一次自检确认没写坏 JSON：

```powershell
.venv\Scripts\python.exe ai_backend\smoke_test.py
```

## 六、记忆系统怎么工作

对应 GDD 5.4 的「长期记忆」。规则在 `characters.json` 的 `memory_design` 里，要点：

| 项 | 规则 |
|---|---|
| 什么会被记住 | 承诺、恩情、冲突、秘密、重要发现。日常寒暄**不记** |
| 每轮注入多少 | 权重最高的 8 条 + 最近 5 条 |
| 衰减 | 每 30 天非秘密条目权重 -1；秘密永不衰减 |
| 上限 | 200 条，超出丢最旧的 |
| 跨角色 | 角色之间的关系变化单独记录，驱动他们**自发互动** |

**「他会用『你还记得你说过什么吗』来施压」** —— 木卡姆艺人这条行为规则，就是记忆系统的活体演示。这也是 GDD 10.2 里「AI 有记忆」这个评委记忆点的落地方式。
