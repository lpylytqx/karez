## 二、作品简介

《坎儿井》是一款以**新疆多民族丝路文化**为题材的 AI 原生 2D 模拟经营游戏。

游戏把镜头放在丝绸之路上最不起眼、却最要命的一个人和一设施上：**一个驿站的驿丞，和一段淤塞的坎儿井**。玩家接手的据点因水源断绝而衰败，必须从"治水"开始——一段一段挖通竖井与暗渠，把天山雪水经地下暗渠引到地表，让荒漠重新长出绿洲；再用绿洲养活的人口去耕作、采集、经商、守卫、放牧、做工、演艺，建起驿馆、巴扎、作坊、晾房、畜栏，接待往来商队，与哈萨克牧民、汉族掌柜、马匪头目、神秘旅人周旋，扛过沙暴、大旱、融雪洪水、寒潮、瘟疫与蝗灾。

游戏的核心设计原则只有一句话：**让文化"活"在角色的日常、劳作、灾难与抉择里，而不是贴一层资料让玩家阅读。**

因此坎儿井不是背景板，它是**唯一的主线**——水决定人口上限，人口决定劳动力，劳动力决定你能挖多快、种多少地、养多少牲畜，整条链条的源头是一个水利工程。同样，十二木卡姆不是一段配乐，它是需要"人在场 + 有一把热瓦普 + 一座奏乐台"才能办起来的一场演出，办完能实打实地把村民的士气和村庄的声望推上去。擀毡子、织地毯、织艾德莱斯绸也不是图鉴条目，而是把羊毛和棉花换成银两、扛过冬天的真实生产链。

## 三、选题背景与文化立意

### 3.0 新疆历史文化的时间纵深

这个题材的分量，在于它**不是风情，是历史**。

- **水利的古老**：坎儿井由竖井、暗渠、明渠、涝坝四部分组成，在吐鲁番、哈密一带
  沿用两千余年；**「坎儿井开凿技艺」已列入国家级非物质文化遗产名录**，
  **「新疆坎儿井」于 2014 年入选世界灌溉工程遗产名录**。也就是说，玩家在游戏里
  一段一段挖的这个东西，是一个**仍在被使用、并已被双重认定的活着的遗产**。
- **丝路的枢纽**：新疆是「丝绸之路：长安—天山廊道的路网」这一世界文化遗产的
  关键区段，交河故城、高昌故城、克孜尔石窟、克孜尔尕哈烽燧等遗产点都在境内。
  游戏里的「驿站 + 商队 + 烽燧」不是凭空设的布景，而是这条廊道上的真实职能。
- **多民族共居**：维吾尔、哈萨克、汉、回等民族在这片土地上共同生活了千百年。
  游戏里同一座驿馆中出现的六族七人，是这一历史事实的日常化呈现。
- **非遗的当代性**：十二木卡姆于 2005 年被联合国教科文组织列入人类口头和
  非物质遗产代表作名录；艾德莱斯绸、擀毡等手工技艺延续至今。它们不是博物馆里的
  标本，而是**可以用生产力与社交关系来玩的东西**。

> 一句话：**我们不是在做一个"新疆风"的游戏，而是在把一份被双重认定的、
> 两千年的水利遗产，做成玩家必须亲自操作的核心机制。**

### 3.1 为什么是坎儿井

坎儿井与万里长城、京杭大运河并称**中国古代三大工程**。它由竖井、暗渠、明渠、涝坝四部分组成，利用天山雪水的地下潜流与地势落差，把水在蒸发量极低的暗渠里输送几十公里，让吐鲁番这样年降水量不足 20 毫米的极端干旱区，长出葡萄、哈密瓜与棉花。

它更重要的价值在于一种**生存智慧**：不与沙漠对抗，而是顺着地下水位走；不追求宏大，而是用几百口竖井、几十公里暗渠，一代人挖一段，持续两千年。

这种"顺应自然、长期主义、集体协作"的气质，正是当代青少年最需要被讲到的故事，而它极少被数字作品认真地讲过。

### 3.2 文化立意（四条）

1. **多民族交融**：维吾尔族老坎匠、木卡姆艺人，哈萨克骑手，汉族商队掌柜，回族厨娘，以及神秘旅人与马匪头目——六族七人在同一座驿站里共处、交易、合作、斗智。丝绸之路的"开放包容"不是口号，而是玩家每天都在处理的具体关系。
2. **人与自然和谐共生**：把"治水"做成游戏唯一主线。玩家的每一次成功，都是"顺着自然规律做对了事"，而不是"战胜了自然"。
3. **非遗传承**：十二木卡姆、艾德莱斯绸、擀毡、热瓦普、诺鲁孜节与古尔邦节，全部以**可操作的生产/社交系统**呈现，非遗是玩法本身。
4. **文化自信与正能量**：用游戏讲好新疆故事。题材独特、地域文化深厚，他人难以复制。

## 四、与新疆文化的结合（核心章节）

> 这一章回答一个问题：**怎么判断一个游戏是"真的在用文化"，还是在"贴文化标签"？**
> 我们的判据是：**把文化元素拆掉，玩法是否随之崩塌。** 拆不掉才是真的长在了一起。

### 4.1 文化元素 → 游戏机制 的逐条映射

| 新疆文化元素 | 在游戏里变成什么机制 | 拆掉会怎样 |
|---|---|---|
| **坎儿井**（四大件：竖井/暗渠/明渠/涝坝） | **6 段竖井**逐段开挖，每段 +55 方/日出水；出水量 × 季节融雪倍率；**涝坝 4 级扩容**（450/900/1600/2600 方）水多时可囤 | 拆掉则整条主线消失，游戏不存在 |
| **涝坝**（蓄水池） | 储水上限 + 水位四档贴图（画面上一眼读出"快干了"） | 旱季无从准备，灾难系统失去对手 |
| **葡萄与葡萄晾房** | 瓜果保质期 **8 天**，晾房把它变成葡萄干——**保质期 120 天** | 过冬的粮食储备策略直接消失 |
| **绿洲农业** | 耕作岗位按田块产粮；**棉花在秋季按人头收**，可织艾德莱斯绸 | 手工产业链断源 |
| **馕** | 保质期 12 天的基础口粮；粮食可存 90 天，但**生粮不如馕顶饿** | 食物腐坏系统失去层次 |
| **草原游牧与哈萨克文化** | **放牧岗位**：1 个牧人照看 8 头；毡房区提供床位与部落亲和 | 畜牧系统失去人手维度 |
| **五个真实畜种** | 阿勒泰细毛羊、绒山羊、双峰驼、库车驴、吐鲁番鸡——各有饲料消耗、繁殖周期、产出与耐寒性 | 畜牧退化成"一个数字" |
| **打猎/抓野畜** | "派人去草原抓野畜"：盘羊→羊、鹅喉羚→山羊、蒙古野驴→驴、野驼→驼；**成功率随去过次数上升**，失败不扣人 | 畜牧没有获取渠道 |
| **擀毡 / 织毯** | 羊毛 3→毡子 1；羊毛 6+织物 2→地毯 1（**羊毛原本毫无用处**） | 养羊没有经济回报，畜牧白做 |
| **艾德莱斯绸** | 棉花 4→绸 1，商队高价收 | 手工链少了最值钱的一环 |
| **热瓦普等民族乐器** | 木料 6+工具 1→热瓦普 1；**是办木卡姆的前置道具** | 音乐系统没有物质基础 |
| **十二木卡姆** | 6 套真实曲目（拉克/且比亚特/木夏吾莱克/恰尔尕/潘吉尕/乌孜哈勒）可演奏，需**奏乐台在场 + 木卡姆艺人在场 + 库里有热瓦普**；消耗 2 行动点、冷却 3 天 | 文化展演变成一句文本 |
| **诺鲁孜节 / 古尔邦节 / 葡萄熟了** | 固定日期触发的节庆，加士气与声望；**古尔邦节：家里牲畜 ≥5 头声望额外 +4** | 时间失去节奏，畜牧的"体面"没有回报 |
| **新疆的四季与灾害** | 一年 120 天 4 季；**沙暴**（烽燧可挡一半）、**大旱**（出水量降到 45%）、**融雪洪水**（围墙可挡）、**寒潮**（冻死牲畜）、**瘟疫**（驿馆可隔离）、**蝗灾** | 玩家没有"过冬"这件事，经营没有压力 |
| **白杨（新疆杨）与胡杨** | 两种树都在植被池里；**秋天整片树池换成金黄**，冬天不摆树、地表换成雪地 | 绿洲失去地域识别度 |
| **巴扎** | 集市建筑，按抽成率进账；商队来访带动成交 | 丝路贸易枢纽的意义消失 |

### 4.2 三类"文化怎么进游戏"的具体手法

**手法一：把文化做成资源瓶颈。**
坎儿井在现实里是"干旱区的唯一解"，在游戏里它就是**唯一的水源**。玩家不是为了体验文化才去挖井，而是**不挖就活不过第七天**。文化在这里是压力，不是装饰。

**手法二：把文化做成前置条件。**
办木卡姆需要"人 + 场地 + 乐器"三件齐备——这是忠实的：木卡姆本来就是需要乐器、场合与传承人的集体活动。玩家为了听一套曲子，必须先种树伐木、建作坊、造乐器。**文化需求驱动了生产链。**

**手法三：把文化做成数值回报，而不是文本奖励。**
古尔邦节的声望加成与牲畜数量挂钩。于是"养牲口"不只是经济行为，它获得了**社会意义**——这正是牧区文化里牲畜的真实地位（财富、体面、待客能力）。数值与民俗在这里是对齐的。

### 4.3 文化呈现的三条自律原则

1. **不编造**：所有非遗元素的名称、形制、节期均取自公开资料。十二木卡姆只做我们确认无误的六套，并在数据文件里**明确标注"是十二套里的六套"**，不假装做全。
2. **不说教**：没有任何一段文本是"科普段落"。文化知识只出现在角色的日常对话、建筑说明、事件后果里。
3. **可核查**：每条文化主张都能在游戏的 `data/*.json` 里找到对应的数据条目（`livestock`、`festivals`、`music`、`crafts`、`disasters` 等 23 个顶层数据段）。

## 五、核心玩法与可玩性

### 5.1 主心骨：据点经营

```
经营据点（挖坎儿井 / 建造 / 生产 / 管人）  ←──┐
        ↓ 缺水、缺物、缺人                  │
   组队与布阵（挑人、配兵种、摆阵型）         │
        ↓                                   │
   派遣探索（6 处丝路地点开图、遇事件）       │
        ↓                                   │
   遭遇战斗或抉择（自由布阵 + 半自动交手）    │
        ↓                                   │
   带回资源 / 情报 / 新成员                  │
        ↓                                   │
   与各方势力打交道（交易 / 谈判 / 结盟）     │
        ↓                                   │
   绿洲壮大、繁荣度提升 ────────────────────┘
```

### 5.2 九个岗位 = 玩家每天真正在做的事

治水、耕作、采集、经商、守卫、炊事、做工、演艺、待命。

**岗位不是数值加成，是互相争夺同一批人。** 多派一个人去挖井，就少一个人种地；多一个人放牧，就少一个人守卫。玩家的每一次分配都在做取舍——这是经营游戏最核心的乐趣来源。

### 5.3 御敌之战：可玩的战斗，而不是看动画

- **自由布阵**：整片布阵区里随便站，不是固定格子。点空地放人、按住人拖动、拖到左侧收回候补。
- **兵种由岗位决定**：守卫→盾卫（血厚攻低）、采集→弓手（射程 52，近战只有 20）、其余→乡勇，待命→平民。**你在分工面板里怎么派人，直接决定战场上有什么兵。**
- **阵型真的影响胜负**：实测评测——同样 5 人打 4 人，摆法不同阵亡相差 **0.00 ~ 3.00 人**（五人队伍里差三个人）。
- **半自动交手**：每 0.62 秒一拍，自动接敌、自动交火，玩家负责的是布阵与开战时机，避免观看动画的枯燥。

### 5.4 灾难与节庆：一年 120 天的节奏感

每天结算时按季节筛选灾难候选并掷骰，遭灾后有 5 天冷却（避免连击把玩家打死）。同时最多一种灾难在发作。灾难不是随机捣乱——**每一种都能被预判、被准备**：

| 灾难 | 季节 | 概率 | 后果 | 谁能挡 |
|---|---|---|---|---|
| 沙暴 | 春·夏 | 17% | 失水、掉士气、牲畜 -10%、建筑受损 | **烽燧**减半 |
| 大旱 | 夏 | 15% | 持续 6 天，出水量降到 45%，田产 60% | — |
| 融雪洪水 | 春 | 12% | 进水 +45 方，但庄稼毁 45% | **围墙** -35% |
| 寒潮 | 秋·冬 | 22% | 牲畜 -30%、人口有概率折损 | **仓库** -30% |
| 瘟疫 | 四季 | 8% | 人口 35% 概率折损、牲畜 -18% | **驿馆** -40%、**居所** -25% |
| 蝗灾 | 夏·秋 | 12% | 庄稼毁 65% | — |

**建筑终于不只是加数值，而是在防具体的天灾。** 这是本作把"经营"和"生存"缝在一起的关键设计。

### 5.5 可玩时长估计

一年 120 天，每天 4 个时段。完整体验一轮"治水存活 → 自给自足 → 接待商队 → 拓展商路 → 文化鼎盛"约 3–5 小时；沙盒继续经营无上限。

## 六、创作与技术实现

> 本章按竞赛《评分标准及奖项设置》对「**游戏、VR/AR/MR/XR**」类作品的分类评价
> 重点组织：**场景构建、交互逻辑、沉浸体验、实时运行、设备适配、性能优化**。
> 为避免"以技术复杂度或功能数量论创新"，本章只讲**为什么这样做**，不罗列规模。

### 6.1 机制创新：把水利工程做成唯一主循环

多数经营游戏的主循环是"资源→建筑→资源"。本作把主循环的**源头换成一件具体的水利工程**：

```
挖竖井 → 出水量↑ → 可灌溉范围↑与人口上限↑ → 劳动力↑
   ↑                                                  ↓
   └──────── 人口被分配到九个岗位（挖井只是其中之一） ←┘
```

这条链条带来的直接后果是：**玩家不是为了"体验文化"才去挖坎儿井，而是不挖就活不过第一周。**
文化在这里不是贴在游戏上的主题皮肤，而是**压力的来源**。这是我们对该题材最重要的一个设计判断。

同理，十二木卡姆不是一段配乐，而是一场需要"**奏乐台在场 + 木卡姆艺人在场 + 库里有热瓦普**"
三件齐备才能办起来的演出——玩家为了听一套曲子，必须先种树、伐木、建作坊、造乐器。
**文化需求反向驱动了生产链。**

### 6.2 场景构建：绿洲的生长是一个看得见的过程

本作采用 **40×22 格、每格 16 像素的固定逻辑画布（640×360）**，整数倍放大到 1280×720。
这个选择让"绿洲生长"成为**画面语言**而不是数字：

| 阶段 | 玩家看到什么 |
|---|---|
| 开局 | 大片黄沙、枯树、一座破驿站 |
| 挖通前两段竖井 | 井口周围出现零星绿意，地面开始有草 |
| 挖到中段 | 绿洲连成片，出现田垄、水渠、白杨 |
| 六段全通 | 完整的绿洲聚落，涝坝蓄满，树池换成浓绿 |
| 入秋 / 入冬 | 树池换金黄 / 不摆树、地表换雪 |

**同一张地图在游戏进程中会被玩家自己改变**——这是"经营"最直接的成就感来源，
也是我们把四季与时段（晨/午/暮/夜）做成全屏调色的原因：让时间也被看见。

### 6.3 交互逻辑：用有限的人力做取舍

核心交互只有一句话：**人永远不够。**

- **九个岗位争夺同一批人**：多派一人挖井，就少一人种地；多一人放牧，就少一人守卫。
- **兵种由岗位决定**：守卫→盾卫（血厚攻低）、采集→弓手（射程 52，近战仅 20）、
  其余→乡勇、待命→平民。**分工面板里怎么派人，直接决定战场上有什么兵**——
  经营与战斗不是两套系统，而是同一套决策的两个出口。
- **战斗是布阵，不是看动画**：整片布阵区可自由站位（点空地放人、按住人拖动、
  拖到左侧收回候补），半自动交手每 0.62 秒一拍。实测评测：同样 5 人打 4 人，
  **摆法不同阵亡相差 0.00 ~ 3.00 人**——阵型真的决定胜负，玩家不是在等结果。
- **灾难可预判、可准备**：六种灾难各有季节与概率，且各有对应的抵挡建筑
  （烽燧挡沙暴、围墙挡洪水、仓库挡寒潮、驿馆与居所减轻瘟疫）。**建筑不只是加数值，
  而是在防具体的天灾**，这是把"经营"与"生存"缝在一起的关键设计。

### 6.4 实时运行、性能优化与设备适配

- **渲染量与窗口大小解耦**：游戏在固定的 640×360 逻辑画布上绘制，再由引擎整数放大
  到窗口尺寸。因此**放大窗口不会增加绘制对象数量**，在集成显卡上也能稳定运行。
- **逻辑与表现分离**：全部数值、状态与结算逻辑独立于渲染；地图坐标、地点、数值
  分别集中在 `sites.gd` 与 `data/numbers.json` 中，改数据不需要动一行绘制代码。
- **AI 不阻塞主循环**：大模型调用走本机独立服务进程，设超时与上下文预算
  （上限 4000 tokens、回复上限 800 tokens）；**服务未就绪或超时时，游戏降级到预设内容
  继续运行，不出现卡顿或卡死**。
- **设备适配的一个真实教训**：团队早期只实现了**中键拖拽**平移地图，自动化测试
  "功能正常"，但玩家实机反馈"移动不了"——**笔记本触控板根本没有中键**。
  此后改为**左键按住拖拽**，并补了一套用真实输入事件走完整管线的探针测试。
  这条教训已成为项目规范：**「机制能用」不等于「玩家能用」。**
- **无需安装环境**：引擎运行时随包附带，解压后双击 `启动游戏.bat` 即玩；
  Windows 10/11 64 位、集成显卡即可。

### 6.5 工程实现：数据驱动架构与可验证性工程

**（1）数据驱动。** 全部玩法数值——水利、建筑、人口、农业、探索、战斗、外交、经济、
牲畜、灾难、加工、节庆、音乐——共 **23 个顶层数据段**统一装在 `data/numbers.json`，
代码只读不写。后期新增的畜牧、灾难、加工、节庆、木卡姆五套系统**全部通过改数据完成**，
未触碰核心逻辑。

**（2）把"看起来能跑"变成"证明能跑"。** 项目自建四套自动化测试，**共 388 项断言**：

| 测试套件 | 断言数 | 覆盖 |
|---|---|---|
| `logic_test` | 170 | 水利平衡、人口、建造、事件结算、畜种与产出 |
| `battle_edge` | 84 | 以少打多、不放人就开战、连续触发、交战中存读档、人口只剩 1 人、数值是否真的来自数据 |
| `livestock_disaster_test` | 119 | 畜牧产出/繁殖/饿死、抓野畜、腐坏、六种灾难的季节筛选与减伤、加工、节庆、地标、木卡姆、畜栏 |
| `input_probe` | 15 | **用真实输入事件走完整管线**（缩放/平移/跟随键），不是直接调函数 |

另有 `verify.py` 做 48 项结构校验（跨文件引用、数值自洽、水平衡、多处实现一致性），
以及色板与素材审计脚本（419 张图逐文件核对 34 色板）。

**这套测试不是摆设**：它逼出过"旧存档读不出来""建造菜单只有两座建筑可点"
这类只在特定路径下才暴露的问题。**自动化测试的价值在于覆盖不顺利的路径，
而截图只能证明顺利跑通的那一条。**

### 6.6 AI 的定位：一个可离线降级的世界活性层

本作使用人工智能工具，但**它不是作品的主轴，而是一个有明确边界的技术层**：

- **AI 只做三件事**：7 位角色的对话文本、事件叙述、以及开发期的代码辅助。
- **其余全部在本地**：数值、状态、存档、所有系统逻辑均由本地代码完成。
- **必须可降级**：AI 服务不可用时，游戏 100% 可玩——对话走团队预先编写的预设内容，
  挖井 / 建造 / 推进 / 事件 / 战斗 / 畜牧全部功能正常。启动器会先探测服务，
  并明确告知玩家当前"走真实 AI"还是"走预设兜底"。
- **人设与知识边界由团队限定**：不允许模型自行编造民族文化的传承谱系与年代。

**这条"可降级"的判断，是本项目把"演示品"变成"可交付产品"的关键工程决策。**
作品对人工智能工具的使用情况，已按竞赛要求在《人工智能工具使用情况说明》中逐项披露。

## 八、应用与传播价值

1. **教育场景**：可作为"丝路文化 / 水利工程 / 干旱区生态"主题的沉浸式教学载体。玩家玩完会真正理解"坎儿井为什么是这个形制"。
2. **文化传播**：以游戏这一年轻人最接受的媒介讲新疆故事；十二木卡姆、艾德莱斯绸等非遗以"可操作"的方式被记住，而不是被读过就忘。
3. **技术示范**：本项目验证了"AI 原生 + 可离线降级"这一架构的可行性，对同类 AI 游戏开发有直接参考价值——**AI 应该是体验的放大器，而不是运行的必要条件。**
4. **可扩展**：23 个数据段全部外置，增加一个新畜种、一场新灾难、一套新曲目**只需改数据**，不碰代码。这让作品具备长期内容扩展能力。
